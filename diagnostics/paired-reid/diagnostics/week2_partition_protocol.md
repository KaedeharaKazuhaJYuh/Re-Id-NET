# Week 2 预先固定的身份分区（只读取训练文件名）

本方案不保存像素，不下载数据，不开始训练，不读取官方 query/gallery。预定 seed 为 20261122，目标校准 / 新评估身份数 120 / 150（仅可行时固定）。其余身份属于未来模型训练。A/B 各 50 个旧开发身份的并集必须由本地批准的历史开发协议重建并核验，不向云端或聊天披露身份、路径或图片。若此收据不能核验，不能把任何输出称作独立验证集。

样例命令（本地）：

```
python -m diagnostics.week2_partition \
  --train-dir /market/bounding_box_train --output-dir /private/week2_partition \
  --seed 20261122 --calibration-identities 120 --evaluation-identities 150 \
  --prior-dev-ids /private/verified_prior_dev_exclusion.json --expect-prior-dev-count 100
```

收据文件是 `{"excluded_identity_ids":[...本地核验的身份编号...]}`。建议分别恢复现有 A/B 开发构造参数、对照检查点归档 `validation_protocol` 和目录摘要，再核对两组各 50 个、并集 100 后写入。CLI 会校验计数和 ID 是否存在，但不能独自证实收据完备、配置未变化或权重祖先。已有旧 Market 训练检查点不可移作新拆分权重。

身份至少出现于两台摄像头才可进入校准或评估。从去除旧开发身份的候选中，以出现摄像头的组合分层，先固定评估、再固定校准，用最大余数分配精确人数、用固定种子散列决定层内顺序；选一个查询/身份，优先分配当前同拆分最少出现的可用查询摄像头，其余图像全部留在相应图库。每个查询都有一个或更多同身份、不同摄像头的图库正例。冻结后不根据得分改人、改摄像头分配、换 seed 或补候选。

输出主清单和 train / calibration / evaluation 三个角色专用清单全部只留在本地；评估角色清单应封存，不能传给训练或调参进程。只有 `aggregate_audit.json` 是不含逐身份编号、图片文件名或路径的汇总，可在获授权时分享。主清单和角色清单哈希均按排序键、紧凑 UTF-8 JSON（不含文件尾换行）计算。源哈希针对顶层文件名列表而不是图片内容及字节，不能用来证明没有篡改图像。下游训练和评估需验证实际收到的角色清单哈希，采样器只吃 model_train，封存评估不参与模型或阈值选择。另行确认并核验，核验从纯 ImageNet 权重（或随机初始化）发起、无旧 Market checkpoint/优化器恢复，再确认真正独立；这不是已完成训练或独立评估。

150 条只是 150 个评估身份的一次配对，单个净救回约 0.667 点、3 个净救回等于 2 点；不代表达到某个统计功效。共享图库仍可能产生依赖，重复种子、掩码和摄像头视图不计作额外独立身份。汇总的假设比较固定两侧 α=.05、目标 0.8、目标 +2 点，配对不一致率设 .05/.10/.20，以正常近似和设计效应 1/1.5/2 做敏感性比较，仅用于判断样本设计是否可支持主张。
